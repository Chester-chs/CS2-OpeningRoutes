# CS2 OpeningRoutes

[English](README.md) | **简体中文**

基于职业赛事 Demo，建立 **各地图的 T/CT 开局控图、道具反制与职业选手示范学习库**，并提供可独立检索的完整道具库。

> **项目状态：方向已更新，暂缓开发。** 2026-10-27 本次只更新 README 和项目规划，不编写应用代码。当前没有应用程序、安装包、解析实验或可运行演示。仍先完善 [POVForge](https://github.com/Chester-chs/CS2-povforge)，以后明确要求恢复开发时再实施本项目。

## 解决什么问题

想学习一个防守位置或第一时间争夺某片区域时，需要知道：带哪些道具、从哪里扔、什么时候扔、谁负责进入或掩护、对手如何反制，以及投完后怎么走。

OpeningRoutes 计划按地图区域组织双方的职业比赛案例，把单颗道具、连续投掷、队友配合、完整行动背景和教学说明连接起来。既能学习 CT 开局防守与反清，也能研究 T 开局抢占控制权及应对 CT 道具的方式。

**预期学习流程：**

地图 → 目标区域 → T/CT → 主动控图或应对反制 → 选择道具与配合方案 → 对比职业选手示范和教学复现 → 收藏练习。

**内容制作流程：**

导入职业赛事 Demo 与来源 → 提取道具和完整回合背景 → 归组投法与方案 → 人工核对用途和动作 → 制作示范与教学 → 发布到本地学习库。

## 计划中的核心能力

- **T/CT 开局控图与反制：** 围绕同一区域组织 T 抢占、CT 阻止或延缓、T 应对防守道具、CT 反清等案例；展示适用条件和对方反应，不承诺固定方案必然有效。
- **完整道具库：** 收录导入比赛中可取得的烟、闪、燃烧弹/燃烧瓶、HE 等投掷记录，按地图、区域、阵营、用途、类型、选手和战队检索；区域教学与单颗道具检索共用内容。
- **不同投法与整套方案：** 按“同一用途 → 不同投法 → 职业案例”整理；另行记录由一人或多人完成的道具组合、顺序、间隔与行动分工。相同落点不自动视为相同投法。
- **职业选手示范：** 查看不同职业选手和战队的真实使用片段，保留投掷前的移动、出手、道具效果与后续站位，附比赛和回合来源。
- **可跟练的教学：** 展示站位、瞄点、出手方式、时机、路线和常见失误。职业比赛原片与自行复现的教学视频明确区分，并标记地图/游戏版本及验证状态。
- **条件与配合：** 说明出生位置、装备、人数、队友需求和对手可观察到的行动；区分单人可完成与需要配合的方案。
- **完整背景与跨比赛比较：** 支持导入比赛的全部可用选手、正式回合和完整回合时间轴；保留个人/全队路线、T 默认片段及手枪局专题。
- **证据与学习笔记：** 展示样本量、日期范围、成功和失败案例；分别保存观察事实、战术解释与练习目标。

## 内容示例与覆盖边界

例如，“Ancient（遗迹）→ 黑屋”可以包含 T 开局争夺、CT 延缓或阻止、T 应对道具、CT 反清，以及各方案下的职业选手投法。这个例子仅说明页面组织方式；具体带什么、按什么顺序扔、如何反制，需核对比赛案例并复现后再写成教学。

“完整道具库”指对导入数据的系统整理与持续扩充，不表示已经收录所有地图上的一切可能投法。明确显示已覆盖地图、比赛、时期、缺失字段与未验证内容。

职业统计只使用可核验的职业赛事 Demo；职业选手的天梯 Demo 不属于目标数据。教学复现独立标记，不计入职业使用次数。

产品不设“单一选手、两三个回合、前 30 秒”的能力上限。开局是主要学习入口，后续反清和行动背景仍可查看。地图和内容可分批交付，验证样本数量不等于产品限制。

## 技术与实施方向

暂定 Python、[demoparser2](https://github.com/LaihoE/demoparser)、地图可视化和本地界面；具体框架、存储与性能目标待恢复开发后确定。

计划先验证职业 Demo 的道具与全回合数据，再完成投法归组、道具检索、职业示范、区域控图与反制方案、教学和收藏。动作识别、道具效果、区域用途和反制解释需要核对；缺失数据不推算为事实。胜率或使用频率不能直接证明最佳投法或反制因果。

以后可探索用 POVForge 制作对应选手和回合的片段，但联动接口尚未设计或实现。
