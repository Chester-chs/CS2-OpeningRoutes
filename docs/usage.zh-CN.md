# 使用 OpeningRoutes 本地预览

当前版本为 v0.2.0 开发预览，提供 Windows 软件与功能网页版。主线为“跟着选手学”：从选手或战队进入地图区域，比较开局选择，再看完整回合和跟练。真实比赛的观察与经过复现核验的完整教学分别展示。

## 跟着选手或战队学一块区域

1. 打开“跟着选手学”，依次选择选手/战队、具体对象、地图、T/CT 和区域。用“战队时期与版本”切换样本范围；同名选手以 SteamID 区分。
2. 查看常驻区域、前 30 秒路线、道具顺序与出手时间。每项都有样本分母；少于 30 回合或 5 场比赛为探索性，至少 5 场才计算置信区间。
3. 在“学习情境”选择“仅手枪局”、经济或比分条件。没有样本时明确显示缺失，不用其他情境的统计补代。
4. 选择一个来源回合。查看真实位置序列、双方区域人数、首次伤害/首杀、双方同期道具，再点“查看全员完整回合”，进入“完整回合”时间轴核对。
5. “保存跟练清单”会保存该回合的实际路线、道具时间与核对步骤。在“我的收藏”勾选进度、记笔记、导出或恢复。无道具的手枪局也能跟练路线。
6. 桌面端可“生成方案草稿”，在“控图与反制”继续填写目的、条件和反制说明。只使用同一回合、对应选手和阵营的开局投掷，排除已标记失误。没有可用道具时只保存跟练单；发布仍须通过完整教学与复现门槛。

手枪局页的“按选手研究手枪局”、CT 研究页的“跟着本图 CT 选手学”和回合详情中的选手按钮都可进入档案。已有教学和职业原片仍从道具详情打开，未发布的原始观察不会在静态站伪装成教程。

桌面端可展开“整理区域与角色组”，用 Demo 原始点位名定义较小区域，或确认同地图、同战队、同阵营、同区域的角色组及日期。个人档案保留，角色组另行统计。区域名字可在“地图区域词表”翻译；不要凭社区叫法猜测边界。

首次进入时后台生成缓存，界面显示计算中，其他页面仍可使用。导入新比赛、修改来源审核、区域或角色定义会使缓存失效。旧数据缺少逐点区域时，重新导入原 Demo 补提取，已有教学与审核保留。找不到原文件的回合明确列为未覆盖。游戏版本目前作为地图兼容分组，不代表精确地图修订号。

区域图显示的是存活人数与持续占位，不包含视线、烟雾遮挡和实际控制权。首次伤害是接触代理，对手同期动作不是已经确认的反制。完整回合始终保留到结束，开局归纳窗口固定为 30 秒。

## Windows 软件

解压 Windows 分发包，进入 `OpeningRoutes` 文件夹，双击 `OpeningRoutes.exe`。请保留同一目录下的 `_internal` 文件夹。

首次启动会载入分发包附带的比赛提取记录（如构建时选择了样本）。自己的资料保存在 `%LOCALAPPDATA%\OpeningRoutes`，更新软件不会覆盖该目录；备份时复制整个目录。程序使用本地 8765 端口，请先关闭其他占用该端口的 OpeningRoutes 实例。

收藏与练习笔记保存在本机的 WebView 浏览器资料中。可在“我的收藏”导出学习记录，也可在另一端导入备份。两端不自动同步。

## 从职业比赛 Demo 到教学

1. 在“数据与内容管理”选择 CS2 `.dem` 文件，填写赛事、对阵、比赛日期和 HTTPS 来源链接。当前单文件最大 2 GiB，不直接导入压缩包。
2. 点击“开始提取”。后台解析正式回合、投掷、道具飞行轨迹和十名选手的完整回合路线；长任务可取消，失败或中断后可重新选择原文件导入。相同文件通过 SHA-256 识别并复用已完成结果。
3. 核对比赛来源、阵容、地图和结果，填写核验记录。未经核验的比赛不会进入职业手枪局统计或正式网页发布包。
4. 在“道具库”选择一条记录。查看原始出手时间、坐标、视角、匹配的飞行轨迹和完整回合背景。路线采用全回合采样，界面明确显示采样频率；出手数据单独保留。
5. 进入“整理教学”，补充战术场景、装备/出生位条件、站位、瞄点、按键、移动/跳跃、时机、效果、配合、失败修正与反制。添加真实站位图、瞄点图和职业比赛原片；原片与教学复现视频分别关联。
6. 在游戏内核验投法，填写验证的游戏/地图版本、日期和核验人。Demo 的视角数值可辅助复现；它不能替代对实际按键、图示和操作步骤的验证。
7. 保存草稿，或通过完整性检查后发布完整教学。修改已验证的操作、图示或地图版本后，需要重新验证并确认，才能继续发布。
8. 在“控图与反制”把投掷组织为方案，记录角色、相对时间、后续行动及对应反制方案。未通过验证的步骤不能成为已验证发布方案。
9. 从“数据与内容管理”导出内容包。完整教学附带职业原片、站位和瞄点资料。来源已核验、记录完整且没有待复核异常的手枪局也可作为比赛记录导出。在“手枪局”选择回合，打开“完整回合”，点击投掷、首杀或炸弹事件可查看双方当时的位置。装备表按全回合收录的实际投掷计数。

外部视频支持 HTTPS MP4/WebM、YouTube 视频及来源链接；本地可添加 MP4/WebM 和 PNG/JPEG/WebP，单媒体最大 250 MiB。外部来源是否可播放取决于该服务及视频当前状态。

## 区域、投法变体、失误道具与异常回合

- **区域：** 每次投掷都带有 Demo 记录的出手区域（投掷者所在点位）。落点区域按生效位置附近出现过的选手点位推测，界面会注明“推测”和距离；推测不到的保持“未知”。道具库可按区域筛选。
- **区域中文名：** 通用点位（出生点、A/B 包点、中路）有默认中文名。社区叫法（如 Ancient 的“黑屋”）不会自动猜测，请在“数据与内容管理 → 地图区域词表”核对后填写。
- **投法变体：** 同地图、同道具类型、同阵营，且出手位置、视角和落点都接近的投掷会自动归为一个候选投法；只是落点相同不会被合并。道具详情的“同一投法的职业案例”列出其他选手的同一投法。勾选两条记录对比时可以“合并为同一投法”，在详情中也能把某次投掷“拆分出来”。人工合并、拆分和命名始终优先于自动归组，并保留修订记录。
- **失误道具：** 丢呲的道具不进入道具库、投法归组、教学、方案和导出，但原始记录保留，完整回合的时间轴上仍会标出“失误”。只有两种情况会自动标记，而且只针对没有人重复过的投掷：烟或 HE 的生效点离出手点不到 200 单位（撞墙弹回或掉在脚下；近乎垂直的投掷不算），或者和某个用过三次以上的成熟投法出手点、瞄点相同，落点却偏离 750 单位以上。在道具库把“教学状态”切到“已标为失误”可以逐条复核；详情里能“标为失误”“不是失误，恢复”或“撤销人工判断”，人工判断始终优先于自动规则。已发布的教学或方案用到的投掷不会被自动隐藏。
- **异常回合：** 重开、缺失结束事件或比赛规则长度未知的回合会进入“异常回合复核”。打开回合，选择“确认为有效正式回合”或“排除，不计入统计”，并写下复核依据；也可以在确认时修正是否为手枪局。排除的回合不会进入手枪局统计和导出。

早于区域功能导入的比赛，再次导入同一 Demo 即可补充区域，不会重复计数；也可运行 `scripts/enrich_places.py`。

## CT 防守研究

左侧导航“CT 防守研究”按地图展示职业 CT 回合的防守阵型（10/15/20 秒各区域人数、常见人数分配、常站位置、20 秒内道具、经济、常用战队与代表回合）、战队习惯（阵型偏好与联盟对比、选手常站位置和转点、道具习惯）、情境检验（经济、比分、上一回合）和学到的站位点。桌面版可以把某个阵型的代表回合一键生成“控图与反制”方案草稿。

方法基于 TAGNet 论文（Zhang 等，IEEE Transactions on Games 2026，DOI 10.1109/TG.2026.3745970），细节、改进点和对照实验见 [ct-research.zh-CN.md](ct-research.zh-CN.md)。区域划分可在“数据与内容管理 → 地图区域词表”里为每个点位选择 A 区 / B 区 / 中路 / CT 后场，阵型会自动重新计算（首次计算约 10 秒，之后有缓存）。

桌面版的资料按地图载入：启动时先载入投掷最多的一张地图，页面顶部“资料按地图载入”显示进度，点击其他地图即可载入；在筛选里选地图、在 CT 防守研究页切换地图，或打开收藏、方案中位于其他地图的投掷时，会自动载入对应地图。

## 手枪局

“手枪局”是独立入口。可以按地图、阵营、选手、战队、比赛和时期筛选，查看冻结结束装备、全队路线、首杀/首亡、下包及回合结果。

胜负案例同时保留。汇总按唯一回合计数，装备分布按选手的冻结结束快照计数。识别依据是 Demo 中的常规半场设置、非热身冻结结束及完成的回合，不按武器类型猜测，也不把加时首回合套成手枪局。异常重开会显示需要复核。

## 网页内容

正式网页版只读取审核发布包，提供选手区域档案、检索、教学、视频、手枪局、完整回合、CT 防守研究与本浏览器的跟练记录。网页不提供 Demo 导入、角色编辑或方案写入。选手档案只使用来源已核验、有效完整回合，每个样本的全员路线一起导出。CT 研究的代表回合只有在该回合也被导出时才能点开。

内容包解压后，其 `manifest.json`、`catalog.json`、`learning`、`timelines` 与 `media` 应放在网页的 `content` 子目录中。通过 HTTP/HTTPS 托管整个网页目录；不要直接双击 HTML。支持站点子路径，档案、目录与回合文件会校验 SHA-256。内容包保持 schema_version 1；没有可选 learning 索引的旧包仍可用，学习新入口会提示尚无档案。

本地网页预览可以包含尚未形成教程的真实提取记录，会明确标为“本地提取记录预览”。这类预览不代表已有完整教学或已公开上线。

## 从源码运行

需要 Python 3.12、uv、Node.js 22.12 或更新版本。已在 Windows / Python 3.12 / Node.js 24 上验证。

```powershell
uv sync --extra dev
cd web
npm ci
npm run build
cd ..
uv run python launch.py
```

本地浏览器模式：

```powershell
uv run python launch.py --browser --port 8765
```

然后打开 `http://127.0.0.1:8765`。源码运行默认使用 `.local/data`；可通过 `--data` 指定自己的数据目录。

构建 Windows 软件：

```powershell
uv run python scripts/build_desktop.py
```

从本地资料生成正式网页构建目录：

```powershell
uv run python scripts/build_web.py --data .local/data
```

仅供自己检查真实提取记录的网页预览：

```powershell
uv run python scripts/build_web.py --data .local/data --local-preview
uv run python -m http.server 8766 --bind 127.0.0.1 --directory artifacts/web-preview
```

## 批量导入职业 Demo

命令在仓库根目录运行。先生成来源表，每个 RAR、ZIP 或独立 DEM 一行；文件名只能提供赛事、对阵的候选文字，日期和来源仍需核对。

```powershell
$env:PYTHONUTF8 = "1"
.venv\Scripts\python.exe scripts\import_folder.py "C:\path\to\demos" --template .local\learning-data\sources.csv
```

填写 CSV 的 `event`、`match`、`date`（YYYY-MM-DD）、`url`（HLTV 比赛页）和 `reviewer`。本人核对后才将该行 `reviewed` 改为 `true`；模板不会覆盖已有表格。未核对或来源不完整的行会保留为 `pending_source`，不入库。下载新包后可生成另一份模板，保留已经填写的表格。

关闭正在写入同一资料库的软件或导入任务，再按明确的地图白名单导入：

```powershell
.venv\Scripts\python.exe scripts\import_folder.py "C:\path\to\demos" --sources .local\learning-data\sources.csv --maps mirage --data .local\data --work .local\learning-data
```

脚本复用桌面端提取流程，先用 SQLite backup 和 timelines 副本备份，再首次写库。原始压缩包和 Demo 保留；解压文件也保存在工作目录的 `staging`，不会自动删除，需预留磁盘空间。RAR 使用系统 `tar`（已验证 Windows bsdtar）；ZIP 使用 Python 自带支持。单个文件上限 2 GiB，单包展开上限 20 GiB，暂存时至少保留 1 GiB 空闲空间。

`results.jsonl` 逐文件记录状态、SHA-256、耗时和错误。再次运行会复核暂存文件并按数据库 SHA 去重，失败文件可重试；旧日志不会代替入库结果。重复文件保留原来源与人工内容，不自动补事实或提升审核状态。`pending_split` 表示分段 Demo，`pending_match_map` 表示同一 HLTV 比赛同地图已有另一份录制，均须人工核对，不能计成新场次。文件名未知地图显示 `unknown_map`；通过白名单的文件还会核对实际 Demo 地图。

## 当前边界

- 覆盖范围取决于自己的导入库。当前本地基准涵盖 Mirage、Ancient、Dust2 的 80 场比赛地图，其中有 21 个回合因缺少本地原 Demo 无法补充新版区域资料；实际档案页会显示覆盖和缺失数。分发包仅附较小样本，不能代表全量库。
- 当前路线为世界坐标示意，保留高度值；尚未提供经校准的分层雷达底图。
- 按键教学、社区区域叫法、配合解释和反制结论需要人工核对。自动投法归组只是候选，需要人工复核后才算确认；自动的失误标记同样只是候选，CT 防守研究的统计不受它影响。
- 落点区域是按附近选手点位推测的，不等于精确的区域边界。
- 录制职业 POV 需要另装 POVForge/HLAE，并且 Demo 必须能被当前 CS2 客户端回放：旧版本录制的 Demo（例如 2025 年 PGL Bucharest，网络版本 14074）在现在的客户端里会被拒绝回放。软件不会自动生成“已验证”教程，真实完整教程的数量以应用实际显示为准。
- Windows 运行需要系统 WebView2；软件包尚未进行代码签名或在其他电脑上验证。
- 当前没有公开托管的在线服务或自动账号同步。静态网站与媒体需要自行部署。
