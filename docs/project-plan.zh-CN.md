# CS2 OpeningRoutes 项目规划

- 更新日期：2026-10-27（Europe/London）
- 状态：v0.1.0 本地开发预览，解析与学习基础流程已实现，真实完整教学内容仍在核验阶段。
- 首版目标：桌面软件与功能网页版，覆盖控图与反制、手枪局、道具库及职业示范。
- 当前实现：Windows 本地软件、可构建的功能网页版、Demo 提取、道具检索、全回合路线、手枪局、教学编辑审核及内容导出；尚无公开发行或公网在线服务。使用方式见[使用说明](usage.zh-CN.md)。

当前真实解析样本来自 PGL Bucharest 2025 Falcons 对 G2 同一系列赛的 Ancient 与 Mirage：39 个正式回合、852 次投掷、4 个手枪局、各地图全部十名选手。全回合路线以 4 Hz 采样，投掷事件另存精确 tick、坐标与视角。当前没有已完成游戏内复现核验的完整教学；自动录制、经校准的分层雷达和系统化投法归组仍需完善。以下规划保留完整目标，不代表所有内容已经交付。

## 1. 产品定位与本次方向调整

建立面向玩家学习的中文职业比赛学习工具，核心包括 **T/CT 开局控图与道具反制、职业选手与战队的手枪局打法、完整道具库和职业示范**。计划提供桌面软件与可实际检索、观看示范的功能网页版。

用户应能从“我要守哪里、抢哪里、应对什么”出发，找到适用方案，理解道具顺序与配合，比较不同职业选手的投法，查看原比赛，再保存为练习内容。

原有需求在新方向下继续保留：

- CT 个人路线与全队防守展开，用于理解到点、投掷前后行动与配合。
- T 全队默认路线、完整回合时间轴及人工选定的默认阶段，用于理解抢占、分散、停留与后续转移。
- 职业选手和战队的手枪局分析是核心模块，首版提供独立入口、筛选、案例与基础汇总，同时用于比较装备受限时的控图和道具方案。

不把产品限制为单一选手、两三个回合或前 30 秒。通过实施顺序和内容分批整理控制难度，不把验证样本写成能力上限。

## 2. 核心使用流程

**按区域学习：**

地图 → 目标区域 → T/CT → 主动控图或应对反制 → 方案及适用条件 → 单颗道具/连续配合 → 职业示范与教学 → 收藏练习。

**按道具查找：**

地图、道具类型、投掷区域或目标区域 → 用途 → 不同投法 → 选手/战队/比赛案例 → 所属控图或反制方案。

**按职业选手研究：**

选手或战队 → 地图、阵营、时期与回合条件 → 道具及方案 → 对比其他职业案例 → 保存观察和练习目标。

同一份投法与比赛记录可被多个方案引用，避免为每个选手或页面重复建立相同内容。

## 3. 地图区域、双方控图与反制

围绕同一区域整理四类场景，具体分类由案例核对后确认：

| 场景 | 内容要求 |
| --- | --- |
| T 开局争夺控制权 | 装备与出生条件、道具准备、移动路线、谁投掷谁进入、时机与后续站位 |
| CT 开局防守、阻止或延缓 | 道具用途、投掷顺序、站位配合、投完后的行动及适用条件 |
| T 应对 CT 防守道具 | 对手可观察到的行动、相关应对案例、需要的道具与配合、局限和失败案例 |
| CT 重新争夺与反清 | 失去区域后的局面、剩余装备、人数、配合与再次进入的案例 |

例如，“Ancient（遗迹）→ 黑屋”可按上述结构组织；“Mirage → B 区/B 二楼方向”可组织相应防守道具与对抗案例。以上仅为内容结构示例，不是已经核验的具体投掷教程或战术配方。中文点位名、别名和地图区域边界需在整理时统一核对。

- 主动控图、延缓、封锁、掩护、反清等用途先由人工标注或确认。
- 方案可以关联对方的应对方案，注明触发条件与比赛证据；不能把两次相邻投掷自动解释为反制因果。
- 区分比赛中观察到的行为、整理者的战术解释和仍待验证的应对建议。
- 不把使用频率或回合胜率直接写成最佳打法，也不把同一套道具当作所有出生位和局面的固定答案。
- 开局作为主要学习入口，后续转移、反清和完整回合背景仍可查看。

## 4. 完整道具库与投法变体

### 4.1 收录与检索

计划保留导入职业比赛中可解析的全部道具投掷记录，覆盖烟、闪、CT 燃烧弹/T 燃烧瓶、HE 等类型；其他类型（如诱饵）在数据可取得时保留并标明类型，不悄悄混入其他类别。

按地图、阵营、区域、用途、道具类型、选手、战队、比赛、日期和验证状态检索。原始投掷记录、候选投法和已审核教学条目应有明确区别，自动提取不等于已可发布为教程。

“完整”指系统整理导入范围内的可用数据，并持续扩充地图和内容，不承诺穷尽所有可能投法。展示覆盖地图、比赛来源、时期、处理状态、缺失字段与不支持项目。

### 4.2 同一用途下的不同投法

组织关系为：**同一用途 → 不同投法 → 各投法的职业选手案例**。

候选分组可以参考道具类型、起点、轨迹、落点与时间；归组规则与阈值需实测后确定，并支持人工合并、拆分和修正。

- 站位、瞄点、站投/跑投/跳投、出手方式、移动与时机存在重要差异时，保留为不同变体。
- 相同落点不自动合并；同一选手也可能有多种投法，多位选手也可能采用同一投法。
- 解析字段不能可靠确定的动作、按键或瞄点标为待核对，不生成确定性的教学说明。
- 比较出手时机、路线、出生位要求与后续行动；“更简单”“更稳定”等评价需有复现依据或明确标为个人评价。

## 5. 单颗道具与整套配合方案

单颗道具记录“如何投掷”；整套方案记录“何时、由谁、按什么顺序使用，以及投完后如何行动”。

每套方案至少规划以下信息：

| 项目 | 需要记录的内容 |
| --- | --- |
| 目标与场景 | 地图区域、阵营、主动控图/反制/反清、用途与适用局面 |
| 前置条件 | 出生位置、装备、人数、队友配合需求及可观察到的对手行为 |
| 执行步骤 | 移动路线、每颗道具的投法引用、投掷者、顺序、时间或间隔 |
| 行动分工 | 投掷、进入、掩护等人工确认的角色及后续站位 |
| 对抗关系 | 对手应对、候选反制、适用限制及相关案例 |
| 职业依据 | 选手、战队、比赛、回合、原 Demo 时间范围、成功与失败案例 |
| 教学与验证 | 原片/复现类型、动作说明、地图/游戏版本、复现日期与验证状态 |
| 学习记录 | 收藏、观察事实、个人解释、练习目标及笔记 |

区分单人连续投掷和多人配合；单颗投法变体与整套方案变体分别管理。时间轴既可按冻结时间结束对齐，也可按经核验的关键事件对齐，不能把不同对齐基准的时间直接混用。

## 6. 职业选手示范与教学复现

### 职业比赛原片

- 从有来源的职业 Demo 定位对应选手与回合，保留投掷准备、移动、出手、效果和后续行动所需的上下文。
- 同一用途下支持切换不同选手、投法与比赛案例，必要时展示队友的同步行动。
- 记录比赛来源、日期、地图、选手、战队、回合和 Demo 时间范围，确保视频能回溯到数据。
- 原回合中的失败、被反制或未达到预期效果的投掷同样可作为案例，不能只收录成功画面。

### 教学复现

- 提供站位图、瞄点图、动作步骤、慢放或重复观看、落点与效果展示、常见失误。
- 自行复现的教学画面明确标记，不冒充原职业选手比赛录像；可关联它所解释的职业案例。
- 标记地图/游戏版本、复现日期与验证状态。旧比赛中曾使用不等于当前版本已验证有效。
- 教学复现不进入职业使用次数、比赛数或胜率的分母。
- 未来可以探索 POVForge 的选手/回合片段生成能力；接口、自动切片、时间映射与工作流均尚未设计或实现。

## 7. 数据来源、覆盖与统计边界

- 职业统计只使用可核验的职业赛事、联赛等比赛 Demo；职业选手天梯、日常匹配和娱乐局不计入。
- 为每场比赛记录赛事、日期、双方队伍、阵容、地图、可核对的来源页面及可取得的版本信息。
- 不凭昵称、SteamID、文件名或下载平台单独认定比赛性质；来源不明的记录标为待确认。
- 起步可使用用户提供的本地职业 Demo 与来源信息；自动下载和大规模采集不是本次确定的前置条件。
- 支持导入比赛的全部可用参赛选手、正式回合、多场比赛和完整回合位置/事件数据。
- 保留出生位置、装备、比分、阵营、暂停、死亡、断线、重开等可取得的背景，缺失值明确显示。
- 按地图与版本区分坐标和区域；处理多层地图的高度差，不直接叠加不同地图或不兼容版本。
- 分页、筛选、按回合读取和按需加载用于可读性及性能，不构成人为的数据数量上限。
- 使用次数、不同回合数、比赛数和选手数分别定义；防止重复导入、重复片段或教学复现重复计数。
- 统计显示分母、时间范围和对应案例；样本不足、阵容变化、缺失与未验证状态单独提示。

教学内容来源于职业案例及其明确标记的复现。个人天梯与职业比赛的自动对比仍不属于当前确认范围。

## 8. 路线背景与手枪局核心模块

### CT 路线与 T 默认

保留个人与全队路线、停留位置、到达标注区域的时间和后续移动，以及跨职业比赛比较。完整回合不等于整段都是默认；默认、执行、反清等阶段和角色由人工标注或确认。观察窗口可选择，不固定截取前 30 秒。

### 手枪局

支持按个人、战队、T/CT 两侧筛选正式手枪局，并汇总装备、站位与路线、行动节奏、道具、首杀/首个阵亡、下包和结果等可取得信息。

正式手枪局依据比赛结构识别，并核对热身、重开和异常回合，不能把买手枪的回合直接视为手枪局。保留胜负两类样本，显示样本量、条件、时期和来源；不由少量回合断言稳定风格或最佳决策。

路线、手枪局与区域控图、道具和职业示范共用数据基础。手枪局属于首版核心验收范围，在桌面端和功能网页版均提供独立入口，不推迟到后续版本。

## 9. 技术方向与内容制作流程

暂定 Python、[demoparser2](https://github.com/LaihoE/demoparser)、地图可视化，以及共用核心界面的桌面端与功能网页版。具体字段、兼容性、框架版本与性能指标通过真实样本确认。

计划流程：

职业 Demo 与来源核验 → 比赛/选手/回合索引 → 全回合位置与道具事件/轨迹 → 候选投法归组 → 人工核对及中文标注 → 职业片段与教学复现 → 区域方案与反制关联 → 检索、收藏与学习。

解析、归组、内容审核、视频生成、方案组织、统计与笔记分开设计。自动提取负责提供候选证据，人工核对负责用途、投法教学与战术解释。自动识别角色、完整战术和自然语言摘要属于后续研究项，不作为第一版可用的必要条件。

## 10. 恢复开发后的分阶段交付

1. **数据可行性验证：** 核对职业比赛来源、全员/正式回合索引、完整回合位置、道具类型/归属/时间/轨迹，以及可用于复现的字段；记录缺失与兼容性。
2. **道具库与职业案例：** 建立可追溯的投掷记录、候选投法归组、人工修正、基础筛选和对应职业示范片段。
3. **控图、反制与手枪局核心模块：** 组织 T/CT 场景、适用条件、单人/多人道具顺序、路线和对抗案例；同步完成手枪局独立入口、筛选、职业案例与基础汇总。
4. **教学与个人学习：** 整理站位/瞄点/动作、复现验证、版本状态、收藏和学习笔记，检查能否照着理解和练习。
5. **双端交付与覆盖扩充：** 完成可运行桌面软件和功能网页版，核验两端的控图、手枪局、道具与示范流程；逐批扩展地图、区域和比赛，依据实测优化性能与深入分析。

这是未来实施顺序，不代表当前启动开发。首批地图、区域与样本待恢复时确定；各阶段不把样本数量变成产品限制。先形成可核验的完整学习流程，再扩大内容覆盖。

## 11. 验收方向

恢复开发时，选取覆盖双方、多选手、多回合、多场比赛及正式手枪局的职业样本，逐项核验：

1. 比赛来源、队伍、选手、正式回合和阵营正确，重复导入不重复计数。
2. 道具类型、投掷者、释放时间、起点、轨迹及落点与 Demo 一致；“释放位置”“落地/爆炸位置”等字段口径清楚。
3. 同用途的不同投法可区分，重复投法可归组，人工修正后案例关联仍正确。
4. 地图坐标、层级和时间对齐正确；抽查 30 秒之后及后段，确认完整背景未被固定窗口截断。
5. 单人/多人方案的装备、角色、顺序、间隔和后续站位可回溯；不把跨回合道具误拼成同一套真实配合。
6. 反制关系区分观察事实与解释，有明确条件和案例；无法确认的内容显示待验证。
7. 视频定位正确，能看到必要上下文；职业原片和教学复现有清楚标记，地图/游戏版本与验证状态可见。
8. 教学动作经过复现核对；不可靠的按键、瞄点和动作数据不显示为已验证说明。
9. 从区域方案能找到单颗道具和不同选手示范，也能从道具反查相关方案；覆盖范围与缺失数据清晰。
10. 正式手枪局清单、统计分母、次数、胜负样本与原比赛一致；教学复现不进入职业统计。
11. 保存并重新打开后，来源、筛选条件、投法/方案关联、收藏与笔记完整保留。
12. 分别评估数据准确性、查找效率和能否跟练；不能用“能播放”代替学习效果验证。

具体误差容许范围、样本、复现次数和性能目标在实施前确定，目前不宣称已经通过上述验收。

## 12. 待确定事项与恢复条件

- 首批地图和区域、中文点位词表、投法归组标准、首批教学内容与界面。
- 视频录制与剪辑方式、POVForge 联动、地图更新后的复核流程。
- 自动采集、自动战术识别、自然语言摘要、云账号、多用户协作和自动云同步属于后续选项。功能网页版已纳入首版范围。
- 当前仅维护规划。用户明确要求恢复开发后，再选样本、核验技术与内容制作成本、明确验收目标并制定实施计划。
