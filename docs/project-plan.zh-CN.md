# CS2 OpeningRoutes 项目规划

更新日期：2026-11-12。当前为 v0.2.0 本地开发预览，学习主线已调整为“选手/战队 × 地图区域”。

## 产品目标

帮助玩家回答：**这个选手或这支战队，在这张地图的这个位置，通常怎样展开、什么时候行动，换一种局面又会怎么打？**

主入口为选手/战队 → 地图 → T/CT → 区域或角色位。输出包括站位分布、前 30 秒移动、道具顺序和时机、经济/比分/手枪局差异、真实完整回合、对手同期动作与跟练清单。职业比赛原片和已有复现教学作为上下文资料连接。

已有道具库、投法归组、视频与 CT 研究功能保留。开发投入集中在人物与位置学习，不继续扩充道具库功能、投法归组或投法视频流水线。

## 已交付的三阶段

| 阶段 | 交付内容 | 检查重点 |
| --- | --- | --- |
| 比赛事实 | 路线逐点区域、首伤/首杀位置、冻结结束装备；CT 快照不变，T 补 0/5/10/15/20/25/30 秒选手快照 | 缺失、死亡、短回合、重复导入与人工内容保留 |
| 档案与缓存 | 个人、战队、人工角色组，游戏版本与转会时期隔离，情境切片和区间，后台缓存及本地 API | SteamID、分母、来源撤回、缓存失效、T 展开 |
| 双端学习 | 跟着选手学、手枪局/CT 研究/完整回合互链、真实样本方案草稿、具体跟练清单、静态发布 | 发布门槛、旧内容包、来源隔离、浏览器操作与性能 |

自动分析提供比赛事实和候选习惯，不自动生成确定性的战术解释。角色合并必须人工确认；“对手同期动作”不能直接写成反制因果。

## 统计定义与样本量

冻结结束为 0 秒，区域由审核过的 Demo 点位集合定义。4 Hz 记录区域内双方存活人数：己方有人且敌方无人持续至少 2 秒为持续占位；双方有人为争夺；均无人为空；缺测为未知。回合末状态和胜负单列。这是占位代理，不包含视线、烟雾遮挡或火力覆盖。

前 30 秒在区域累计停留至少 2 秒，或向该区域投掷，才进入该区域档案。统计分母是参与本区域的回合，不是选手所有上场回合；一个回合可属于多个区域。首伤作接触代理，首杀和道具时序保留来源。完整回放延伸到回合结束。

身份按 SteamID，昵称只用于展示。转会时期、队伍阵容和游戏版本分开；游戏版本作为保守的地图兼容分组，并非精确地图修订哈希。未知版本不跨比赛合并。同队同角色汇总需人工确认成员、区域和日期，保留个人资料。

每个档案和情境列唯一回合、比赛地图与选手数量。少于 30 回合或 5 场比赛标为探索性；至少 5 场按比赛整块重抽样 400 次计算习惯占比 95% 区间。使用频率和胜负只描述样本，不代表最优路线。应优先补充同选手、同地图、同版本及相近时期的职业 Demo，再考虑角色组，避免用盲目合并掩盖小样本。

## 教学、跟练与公开内容

选中真实回合后，生成保留来源、选手、同回合道具和时机的方案草稿；被标记失误的道具不会进入新方案。无道具样本只生成路线跟练清单。方案发布仍要求各步骤的完整教学与游戏内复现证据。此次流程不启动 CS2，也不新增复现核验结论。

桌面端负责导入、区域/角色定义和方案整理。静态网页提供档案、对应完整回合、已有发布教学和浏览器跟练记录，不包含草稿或私人笔记。内容包保持 schema_version 1，以可选 learning/index.json 增加档案；旧包仍能浏览原有内容，新入口明确提示资料缺失。文件按 SHA-256 校验。

## 验收与边界

- Mirage 的 T/CT 档案与手枪局均可完整浏览，所有档案显示样本和不确定性。
- 在 80 场、1,757 回合的本地基准库实测，10 次浏览器访问的 p95：缓存就绪档案不超过 3 秒，全库首屏可用不超过 4 秒；冷计算另计。
- 自动化覆盖提取、统计、身份、缓存、来源/发布门槛、旧包兼容、持久化和双端回放；保留原有 Playwright 流程。
- 实现沿用 SQLite 既有表，新增定义表；不改变旧 catalog 必需字段。原始 Demo、数据缓存、构建产物和私人资料不纳入仓库。

本次基准库有 1,691 个来源已核验有效回合，其中 1,670 个具备新版区域资料，形成 6,185 份个人/战队/区域/时期档案。另有 21 个回合缺少可补提取的本地原 Demo，明确显示为未覆盖。档案数量不等于独立教学数量；大量细分档案仍属于探索性样本。

后续先验证区域划分、角色判断和学习效果，按需补充 Demo。自动战术识别、视野控制推断、云账号与跨设备同步、公开托管和新视频生产不在本次范围。
