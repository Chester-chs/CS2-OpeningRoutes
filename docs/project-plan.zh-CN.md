# CS2 OpeningRoutes 项目规划

- 记录日期：2026-10-20（Europe/London）
- 状态：已确认方向，暂缓开发。
- 当前优先事项：先完善 CS2 POVForge。
- 恢复条件：用户以后明确要求继续本项目；不自动开始开发。
- 当前产物：中英文项目介绍与本规划。没有产品代码、解析实验或运行结果。

## 1. 已确认的方向

用户希望通过职业比赛 Demo 学习选手开局打法，明确认可了 CT 开局防守路线、T 默认前期路线这两个场景。

目标是做一个初学者能够逐步理解、借助 AI 完成的小工具，规模接近现有个人仓库。首要使用者是用户自己，也可以让有相同学习需求的玩家试用。

“CT 开局”和“T 默认”是学习场景标签，不代表软件可以从路线自动识别战术意图。

## 2. 使用场景示例

用户想研究某名职业选手在一个位置的开局，人工挑选三个同阵营回合：

1. 查看三局不同的出生位置与初始装备。
2. 对比前 30 秒的移动路线与停留位置。
3. 查看选定时间时，选手分别走到了哪里。
4. 必要时在原 Demo 或 POV 视频中核对当时的信息与动作。
5. 写下观察、自己的解释，以及下一次练习想尝试的内容。

路线相似不能证明战术相同；出生位置不同造成的时间差，也不能直接解释成执行失误。

## 3. 第一版候选范围

以下是保存的推荐范围，恢复开发时仍需复核，不能视为已验证的实现方案。

| 项目 | 第一版建议 |
| --- | --- |
| 地图 | 一张，具体地图待用户选择 |
| 数据 | 用户自行提供的本地职业比赛 Demo |
| 选手 | 一次选择一名选手 |
| 回合 | 人工挑选同一阵营的两到三个回合 |
| 时间范围 | 冻结时间结束后前 30 秒 |
| 显示 | 静态雷达、不同颜色路线、简单时间选择控件 |
| 背景 | 来源、回合、阵营、出生位置、初始装备；不可用项明确标记 |
| 保存 | 本地学习案例与用户笔记 |

第一版先完成同一选手跨回合比较。不同职业选手之间的对比、自己的 Demo 与职业 Demo 的对比，后续另行评估。

## 4. 学习案例应保存的内容

- 比赛与 Demo 来源说明、地图、选手标识、回合标识和阵营。
- Demo 文件标识与解析器版本，避免文件同名或版本变化后错误复用数据。
- 时间基准、比较范围及各回合背景。
- 展示所需的坐标与时间数据。
- 分开的“观察到的事实”“我的理解”“下次练习目标”三个笔记区域。
- 数据缺失与验证状态。

## 5. 技术方向与主要不确定性

建议使用 Python 和已有的 demoparser2 读取坐标与事件，再用绘图库生成雷达路线。保持数据解析、时间对齐、地图显示和案例保存各自独立，方便逐步学习与排错。

界面可考虑 Python 本地界面；不在当前阶段锁定具体框架。存储也待样本验证后确定，优先选择简单、可备份的本地格式。

恢复时首先核实：

- 目标 Demo 来源与版本能否正确解析。
- 回合与冻结时间结束事件能否可靠识别。
- 依据 Demo 时间信息换算相对秒数，不能未经核实写死 tick 换算方式。
- 雷达图与地图版本是否匹配，世界坐标到图像坐标的转换是否准确。
- 死亡、暂停、缺失数据和读取失败怎样表示；不把缺失数据画成正常路线。
- 只提取所选回合必要的数据，实测普通电脑上的时间与内存需求。

## 6. 验收方式

先使用一份真实 Demo、同阵营的三个回合建立最小验证样本：

1. 核对选手、阵营、回合与开局背景，确认没有串局或选错人。
2. 在原 Demo 中抽查冻结时间结束及数个相对时间点，核对路线位置。
3. 将时间精度和坐标误差记录下来，再决定可接受阈值，不提前宣称精确。
4. 核实死亡后没有继续显示成正常移动；缺失数据与不支持情况有提示。
5. 保存案例、关闭后重新打开，确认选择与笔记完整保留。
6. 录制“选择三个回合 → 对比路线时间 → 保存学习结论”的演示。

这些检查验证工具是否正确展示数据。是否帮助用户学到可应用的打法，需要额外试用和反馈，不能从图表正确直接推导。

## 7. 后续可能的发展

- 从前 30 秒扩展到用户指定的片段，以便研究较长的 T 默认。
- 增加明确的伤害、死亡和道具事件标记。
- 对比不同职业选手，或将个人 Demo 与职业参考案例对照。
- 引用 POVForge 导出的视频，辅助理解单人视角。

以上均为候选，不纳入第一版承诺。POVForge 的接口和本项目的联动方式尚未设计。

## 8. 恢复开发时的顺序

1. 确认用户已准备从 POVForge 转回本项目。
2. 选地图、阵营、学习位置和一份真实 Demo。
3. 复核同类工具，确认这个个人学习流程仍值得做。
4. 更新本设计，确定第一版功能及可验证的成功标准。
5. 用户审阅具体设计后，再制定实施计划并决定开发方式。

## 9. 调研起点

- [demoparser2](https://github.com/LaihoE/demoparser)：已有 Python / JavaScript Demo 解析能力。
- [CS Demo Manager 的 2D 回放](https://cs-demo-manager.com/docs/guides/2d-viewer)与[评论功能](https://cs-demo-manager.com/docs/guides/comments)：已有回放和笔记功能可供参照。
- [CS2.CAM](https://cs2.cam/)：已有多回合叠加与战术分析功能，不把基础路线对比宣传为全新能力。

这些是设计参考，不是本项目已经完成的功能。恢复时重新核查相关工具与解析器情况。
