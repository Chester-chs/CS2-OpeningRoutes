# CS2 OpeningRoutes 项目规划

- 记录日期：2026-10-20（Europe/London）
- 状态：已确认方向，暂缓开发；本次仅修订需求文档。
- 当前优先事项：先完善 CS2 POVForge。
- 恢复条件：用户以后明确要求继续本项目；不自动开始开发。
- 当前产物：中英文介绍与本规划。没有产品代码、解析实验或运行结果。

## 1. 已确认的目标

只通过职业赛事 Demo，分析和学习职业选手与职业战队的打法。三个并列核心模块为：

1. **CT 开局防守方式：** 研究个人路线与全队开局防守展开。
2. **T 默认整体路线：** 研究全队在回合中的站位、分散控图、停留与转移，支持完整回合及具体默认阶段。
3. **职业选手与战队的手枪局风格：** 基于多场职业比赛的正式手枪局，比较个人与团队行为倾向，辅助分析与学习。

用户已明确纠正：不能把产品限制为单一选手、两三个回合或冻结时间结束后前 30 秒。验证时使用少量样本是工程方法，不是产品能力上限。

首要使用者是用户自己。借助 AI 分阶段实现并逐步理解技术；通过实施顺序控制难度，不删除已确认的核心需求。

## 2. 职业赛事 Demo 的数据边界

- 目标数据是职业战队参加赛事、联赛等职业比赛产生的 Demo。
- 职业选手的天梯、日常匹配、娱乐局及非职业比赛个人 Demo，不进入目标分析数据集。
- 不能仅凭选手昵称、SteamID、文件名或下载平台判断“职业比赛”。
- 为每场比赛记录赛事、参赛队伍、比赛日期、地图和可核对的比赛页面/来源。
- 同一个平台可能承载职业赛事和天梯，按实际比赛性质与来源核验，不按平台名称一刀切。
- 无法核验比赛性质的文件标为来源待确认，不能直接计入职业比赛统计。
- 第一阶段可由用户提供本地职业赛事 Demo 和来源信息；自动下载与大规模赛事采集尚未确定。

## 3. 数据覆盖与筛选

| 维度 | 已确认的产品要求 |
| --- | --- |
| 选手 | 支持导入比赛中可用的全部参赛选手，可选择个人或多人查看 |
| 战队 | 支持战队维度分析与全队路线展示 |
| 回合 | 覆盖正式比赛回合，不限定为两三个回合 |
| 多场比赛 | 支持按比赛、选手和战队组织跨比赛案例与统计 |
| 时间 | 保存研究所需的完整回合位置/事件数据，可查看全局及选取片段 |
| 专题 | CT 开局、T 默认、手枪局；前两者不局限于手枪局 |
| 地图 | 按地图区分数据与坐标；首批地图集合待确定，不把不同地图直接叠加 |
| 背景 | 赛事、日期、队伍、阵容、阵营、出生点、装备、比分和地图版本等可用信息 |

界面可分组、分页或按需加载，以减少图形拥挤和内存占用；这些策略不应成为可分析选手数、回合数的任意上限。

不同选手、战队和比赛的比较，应在相同地图与阵营等可解释条件下进行，并显示阵容、出生点、装备和样本时期等差异。

## 4. CT 开局防守模块

- 选择地图、队伍、选手与正式回合，查看个人和全队的开局展开。
- 展示移动路线、停留位置、到达用户标注区域的时间，以及后续移动。
- 按冻结时间结束对齐开局，比较多个回合或比赛中的差异。
- CT 开局观察窗口由用户选择，不固定为某个秒数。
- 保留出生点和装备背景，避免把出生差异直接解释成执行失误。
- 区域名称、角色与战术含义先由人工标注或确认，不把轨迹直接当作完整意图。

## 5. T 默认整体路线模块

- 全队视角是核心需求，同时支持选定个人查看。
- 提供完整回合路线与时间轴，观察分散、停留、控图过程与后续转移。
- 用户可选择默认片段，查看该片段的全队行动，不固定在前 30 秒截断。
- 完整回合不等于整段都属于默认；默认、执行、回防等阶段先由人工标注或确认。
- 比较不同回合与战队的路线和节奏，并能回到原回合检查。

## 6. 职业选手与战队的手枪局风格模块

### 分析对象

同时支持个人和战队，分别汇总 T、CT 两侧的正式手枪局。保留成功与失败回合，不能只筛获胜案例。

手枪局应依据正式比赛结构识别，并核验热身、重开、异常回合与解析问题；不能把“购买了手枪的回合”直接当成手枪局。

### 候选分析维度

以下是设计维度，具体数据是否可取得、如何计算，恢复开发后通过样本确认：

- **装备选择：** 个人与全队的武器、护甲和道具配置。
- **CT 开局：** 站位分布、个人路线、到点时间与后续移动。
- **T 路线：** 队伍如何分散、集合和转移，在哪些人工标注区域停留或进入。
- **行动节奏：** 到达标注区域的时间、首次伤害/击杀事件时间、下包时间等。
- **道具配合：** 可核验道具事件的类型、位置与时间；缺失时不推算成事实。
- **开局交战：** 首杀、首个阵亡和后续击杀的事件顺序；不能据此直接断言谁先看到谁。
- **结果背景：** 下包位置、回合结果、关键事件，以及与路线/装备的关联分布。

### 结果呈现

- 统计与路线/时间分布显示样本量、比赛范围、日期、地图与阵营。
- 每项摘要可定位到支持它的具体比赛和回合。
- “倾向前压”“偏向某路线”等描述必须有明确条件或人工标签。
- 样本不足、字段缺失和阵容变化单独提示，不由少量回合断言稳定风格。
- 展示打法与结果的关联，不把关联写成因果或最佳打法推荐。
- 分开保存“统计/观察事实”“我的战术解释”“学习与练习目标”。

## 7. 技术方向与分阶段交付

暂定 Python、demoparser2、绘图和本地界面。界面框架、存储方式、首批地图与性能指标尚未确定。

1. **职业比赛数据基础：** 来源记录，比赛/队伍/选手/正式回合索引，完整回合所需的位置与事件数据。
2. **路线学习：** 地图坐标、时间轴、个人/全队切换、CT 开局与 T 默认片段、跨回合/比赛比较。
3. **手枪局分析：** 正式手枪局识别、个人/团队汇总、指标口径与回合追溯。
4. **学习案例保存与验证：** 笔记、对比条件、来源、数据版本与验证状态。

这是后续实施顺序，不表示当前开始开发，也不把先验样本数量改成产品限制。

解析、时间对齐、地图显示、统计和案例保存应保持独立。实测后再选择缓存、按回合读取和显示分组等性能策略。

## 8. 验收方向

恢复开发时，准备含多名选手、多回合和多场比赛的职业赛事样本，覆盖 CT/T 与正式手枪局：

1. 核对比赛来源、队伍、选手与回合索引，避免串局、串人和混入天梯。
2. 查看个人与全队数据，确认超过三回合的选取和比较流程可用。
3. 抽查冻结时间结束、30 秒之后及回合后段的位置与时间，确认没有固定窗口截断。
4. 将正式手枪局清单与原比赛核对，保留成功和失败回合并处理重开等异常。
5. 抽查统计值、分母与样本数，逐项回溯到原回合和字段。
6. 核实死亡、暂停、缺失与不支持情况有明确表示；相对时间换算不未经核实写死。
7. 保存后重新打开，比较条件、来源与笔记完整保留。

具体验收样本与可接受误差在开发前确定。数据展示准确与是否帮助学到打法，应分别评估。
